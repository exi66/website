## Problem

A regular ping (ICMP) takes a different path and is handled differently by the server than game data, so it often shows a different latency from what you get in the game. I needed to measure the game connection itself, without sending separate requests to the server.

## Solution

The app captures TCP packets on a network interface and matches sent segments with ACKs from the server. The time difference is the RTT, shown on a live graph.

What it takes to get honest numbers:

- **Retransmissions are not measured (Karn's algorithm).** It's unknown which copy the ACK belongs to, so such a sample would skew the result.
- **One ACK often confirms several segments.** Only the newest one counts, otherwise older segments would overstate the latency.
- **TCP sequence numbers wrap around at 2³².** Comparisons are done modulo 2³² (RFC 1982), so measurement doesn't break at the wraparound.
- **Time comes from Npcap capture timestamps**, not from when the packet is processed, so UI thread load doesn't affect the result.
- **Capture and UI run on separate threads**, and the connection state is thread-safe.

## Quality

The measurement logic is separated from the UI and packet capture and covered by 27 unit tests. On a tag, GitHub Actions runs the tests, builds a single-file `.exe` for x64 and x86 and publishes a release.
